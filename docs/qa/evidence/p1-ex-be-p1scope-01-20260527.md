## 1. Problem statement (P1)

Some HRM modules had **list scope rollup** via `resolveHrmListScope` (group CEO `company_id=main` expands to member slugs) but **create paths** persisted `company_id=main` into TEXT tables.

Result: Newly created rows became **invisible** to list APIs (because lists filter by member slugs), and scope parity became inconsistent across modules.

---

## 2. Changes implemented

### 2.1 Shared helper: TEXT create-path company_id resolver

- Added `resolveHrmPersistCompanyIdText()` in `apps/api/hrm-api/src/common/hrm-list-scope.ts`
  - Group CEO rollup write: `main` → `holding` (TEXT)
  - Member tenant write: keeps `main`
  - Does **not** widen access: persisted `company_id` must be inside `resolveHrmListScope(...).companyIds`

### 2.2 Adopt helper for create paths (EX-SA01-P1-01)

- `contracts-insurance`
  - `ContractsInsuranceService.createContract()` now persists via `resolveHrmPersistCompanyIdText(authorization, payload.company_id)`
  - `ContractsInsuranceService.createInsuranceRecord()` same
  - Controller passes `authorization` down to service (keeps `resolveScopeContext` guard unchanged)

- `recruitment`
  - `RecruitmentService.createJobRequisition()` now persists via `resolveHrmPersistCompanyIdText(authorization, payload.company_id)`
  - Schema uses `company_id TEXT` (keeps backward-compatible `ALTER COLUMN ...::text`)
  - Controller passes `authorization` down to service
  - DTO `CreateJobRequisitionDto.company_id` updated to accept slug (`IsString`, `MaxLength(64)`) to match portal `main` contract

- `performance`
  - `PerformanceService.createCycle()` now persists via `resolveHrmPersistCompanyIdText(authorization, payload.company_id)`
  - Controller passes `authorization` down to service
