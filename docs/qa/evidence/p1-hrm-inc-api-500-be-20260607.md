## Root cause

User screenshot: `GET /api/hrm/contracts-insurance/contracts?page=1&page_size=100` → **500** `HRM-SYS-001`.

`qualifyContractInsuranceFilters` used global `\bemployee_id\b` replacement on clauses that already contained `ec.employee_id` (from `pushResolvableEmployeeScope` with prefixed column). PostgreSQL received invalid column `ec.ec.employee_id`.

Secondary risk: subquery clauses with `FROM public.employees` had inner `company_id` incorrectly prefixed when skip logic was absent.

---

## Fix summary

| File | Change |
|------|--------|
| `contracts-insurance.service.ts` | `qualifyContractInsuranceFilters` — negative lookbehind `(?<!ec\.)` / `(?<!ir\.)` on `company_id`, `employee_id`, `status`; workforce IN-subquery qualifies only leading `employee_id` |
| `contracts-insurance.service.ts` | `listContracts`, `getContractById`, `listInsurance` — unqualified `employee_id` / `status` before qualify pass |
| `contracts-insurance.service.spec.ts` | P1-HRM-INC-API-500-01 regressions: `listContracts` paginated + `listExpiringContracts` assert SQL never contains `ec.ec.employee_id` |
