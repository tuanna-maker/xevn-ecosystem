## Root cause (QA-W2 L2-W2)

`ListTasksQueryDto` / `ListServiceRequestsQueryDto` / create DTOs used `@IsUUID()` → **400** `HRM-VAL-001` when portal sent `company_id=main`. List SQL used `$1::uuid` without `resolveHrmListScope` rollup.

## Code changes

### DTO — slug-friendly `company_id`

- `list-tasks.query.dto.ts`, `list-service-requests.query.dto.ts`, `create-task.dto.ts`, `create-service-request.dto.ts` → `@IsString()` `@MaxLength(64)` (parity with attendance `listUpdateRequests`).

### Scope helpers (`hrm-list-scope.ts`)

- `HRM_COMPANY_UUID_BY_SLUG` — pilot UUID map (seed-full-ecosystem).
- `pushCompanyIdUuidFilter` — `company_id UUID` tables with group `ANY(uuid[])`.
- `resolveHrmOperationsPersistCompanyId` — `main` → holding UUID on create.
- `companyIdsToUuidList` — maps bare `main` to holding UUID as safety net.

### Operations service

- `listTasks` / `listServiceRequests` — `resolveHrmListScope(authorization, query.company_id, { tenantId })` + `pushCompanyIdUuidFilter`.
- `createTask` / `createServiceRequest` — persist via `resolveHrmOperationsPersistCompanyId`.
- `getSummary` — passes `tenantId` into scope; `countByScope` uses `company_uuid` mode (not broken `::text` slug match on UUID columns).

### Tests

- `hrm-list-scope.spec.ts` — UUID filter + persist mapping.
- `operations.service.spec.ts` — main rollup list/create + summary tenant context.
- `operations.controller.spec.ts` — `HRM-OP-02`, `HRM-SV-02` main acceptance.
