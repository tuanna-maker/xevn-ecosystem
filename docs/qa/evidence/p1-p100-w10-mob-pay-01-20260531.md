## Problem

After MOB-FIX, payroll screens used `getAttendanceCompanyId()` → legal UUID in `company_id` query. Pilot seed and `tmp-p1-resid-c03-probe.mjs` use **`company_id=main`** for group CEO rollup on `GET /payroll/payslips`. BE `resolveHrmListScope` only applies workforce rollup when `requestedCompanyId === 'main'`. UUID query + `employee_id` filter returned **0** rows on device while API probe returned **2**.

## Fix

| Area | Change |
|------|--------|
| `companyWireScope.ts` | **`resolvePayrollQueryCompanyId()`** — when scope slug is `main`, query param stays `main`; else wire UUID. Header path unchanged (`resolveWireCompanyId` / never `main` on `x-company-id`). |
| `AuthContext.tsx` | **`getPayrollQueryCompanyId()`** exposed to payroll features |
| `PayrollSummaryScreen.tsx` | periods list uses payroll query scope |
| `PayslipListScreen.tsx` | payslips list uses payroll query scope |
| `PayslipDetailScreen.tsx` | payslip detail fetch uses payroll query scope |
| `InAppNotificationsScreen.tsx` | payroll periods widget uses payroll query scope |

**Split contract (unchanged header, fixed query):**

| Wire | Value |
|------|--------|
| `x-company-id` | Legal UUID (`7b626710-…`) — never literal `main` |
| `company_id` query (payroll only) | `main` when JWT/membership scope slug is `main` |
