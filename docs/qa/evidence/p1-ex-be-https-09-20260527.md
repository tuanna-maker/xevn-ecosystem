## Root cause (QA R8)

Under `company_id=main` (group CEO rollup), **contracts** and **insurance** lists filtered only `ec.company_id` / `ir.company_id` ∈ `GROUP_MEMBER_SLUGS` and required a live employee row (`e.archived_at IS NULL`), but did **not** apply the same **master tenant partition** as `GET /employees/{id}` (`pushEmployeeListScopeFilters` / `custom_fields.tenant_id`).

Result: list returned `employee_id` values (e.g. `ecb3d81a-…`, `60356a9d-…`) that are **not** in `GET /employees?company_id=main` → detail **404** `HRM-EMP-404` (J-HRM-01, J-HRM-04).

## Fix

| Area | Change |
|---|---|
| `contracts-insurance.service.ts` | `pushWorkforceEmployeeScopeFilter` on `ec.employee_id` / `ir.employee_id` when `masterTenantPartition` or `memberTenantId` (same subquery as attendance/payroll). Applied to `listContracts`, `getContractById`, `listInsurance`, and expiring list endpoints. |
| Filter qualification | `qualifyContractInsuranceFilters` skips clauses containing `FROM public.employees` so subquery `company_id` is not wrongly prefixed with `ec.` / `ir.`. |
| Tests | J-HRM-01/04 regression in `contracts-insurance.service.spec.ts`; workforce alignment in `hrm-list-scope.spec.ts`. |

Employees `getEmployeeById` path unchanged (already uses `pushEmployeeListScopeFilters` + `skipTenantPartition` fallback per HTTPS-08).
