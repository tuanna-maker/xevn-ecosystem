## Problem (SA register)

Group CEO JWT `companyId=main` must not send `holding` (or other group alias) to **strict** XBOS modules (`workflow-engine`, `assets`, `position-rbac`, `asset-request`, `infrastructure`) — causes **409 SCOPE_CONTEXT_MISMATCH** on pilot cross-nav. Holding alias is allowed only on **KPI rollup** and **group-legal-read** surfaces per ADR §4.

## Deliverables

| Item | Implementation |
|------|----------------|
| XBOS API scope route table | `apps/web/web-portal/src/integrations/xbosApiScopeRouteTable.ts` — modes: `strict` \| `kpi-rollup` \| `group-legal-read` |
| Central resolver | `resolveXbosApiCompanyIdForPath` / `resolveXbosStrictCompanyId` in `commandCenterScope.ts` — coerces `holding` → `main` on strict |
| HTTP layer | `xbosHttp.ts` — normalizes `x-company-id` from path before every XBOS call |
| Strict API clients | `assetRequestApi`, `positionRbacApi`, `raciGovernanceApi` headers use strict resolver |
| Legal-read query | `businessMasterApi`, `portalAlertsApi` (catalog + KPI alerts) use path-aware resolver |
| CC deep links | `commandCenterSettingsDeepLink` / `parseCommandCenterSettingsDeepLink` — **no** `companyId` in URL; `wfId` / `wfInstanceId` for workflow |
| CC hydrate | `CommandCenterPage` — parse `?settings=workflow&wfId=` / `wfInstanceId=`; ignore legacy `companyId=holding` |
