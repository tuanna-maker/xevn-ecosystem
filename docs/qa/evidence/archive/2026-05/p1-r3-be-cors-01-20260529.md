## Root cause

`xbos-api` used shared `resolveCorsOptions()` from `@xevn/platform-core`. When `NODE_ENV` is not `production` **and** `CORS_ALLOWED_ORIGINS` is absent at process boot, Nest gets `origin: true` (reflect-any-origin). Pilot VPS **hrm-api** blocked evil origins; **xbos-api** echoed `https://evil.example` (QA `P1-R3-QA-01-R1` §2).

Likely contributing factors on pilot: xbos container not inheriting deploy `.env` whitelist the same way as hrm, or `NODE_ENV` / `CORS_ALLOWED_ORIGINS` not applied before CORS init.

---

## Code changes

| File | Change |
|------|--------|
| `apps/api/xbos-api/src/common/xbos-cors.ts` | `resolveXbosCorsOptions()` — **never** `origin: true`; whitelist when `NODE_ENV=production`, `CORS_ALLOWED_ORIGINS` set, or non-dev `SERVICE_JWT_SECRET` (deployed pilot) |
| `apps/api/xbos-api/src/main.ts` | `enableCors(resolveXbosCorsOptions())` |
| `apps/api/xbos-api/src/load-env.ts` | `findMonorepoRoot()` — locate `deploy/xevn-ecosystem/.env` from package cwd, repo root, or `dist/` |

Behavior matches **hrm production**: only origins in `CORS_ALLOWED_ORIGINS`; non-whitelisted `Origin` → no ACAO echo (null/absent).
