## Problem

`du-lich.ceo@xe.vn` JWT carries scope slug `main` in `company_id` and legal-entity UUID `7b626710-02eb-4a39-89c5-e9a90ecc74ff` in `company_uuid`. DEVICE-02 showed UUID on dashboard scope card but outbound list/approve calls still behaved as scope slug `main` when SecureStore lacked backfilled `company_uuid` or auth config forwarded slug to `hrmRequest`.

## Fix

| Area | Change |
|------|--------|
| `companyWireScope.ts` | **New** — `resolveWireCompanyId()` backfills legal UUID from SecureStore → active membership → JWT `company_uuid`; blocks wire slug `main` |
| `jwtClaims.ts` | Parse `company_uuid` from mobile JWT payload |
| `hrmApiClient.ts` | `resolveHrmCompanyHeaderId()` returns `''` for literal `main` (never on wire); header still set from resolved UUID via auth config |
| `AuthContext.tsx` | `buildHrmAuthConfig()` — every `getHrmAuth()` / `getAttendanceCompanyId()` / select-membership / refresh uses wire UUID; hydrate backfills + persists `COMPANY_UUID` from JWT/memberships |

**Wire contract:** all HRM REST calls (`x-company-id` header + `company_id` query/body) use legal-entity UUID when membership/JWT provides it — never literal `main`.
