## Architecture and stack governance

### Strengths

1. **Module boundaries** — KPI, catalog-governance, org-foundation, platform-audit remain separate Nest modules; scope resolution extracted (`kpi-rollup-scope.ts`, `hrm-list-scope.ts`) rather than controller sprawl — aligns with SOLID (S, D).
2. **Deterministic errors** — prior 400/409/404 probes resolved with explicit DTO/scope rules and jest coverage; no silent fallback to mock on dept templates (FE03 strict policy).
3. **Platform NFR** — `xbos-api` / `hrm-api` integrate `@xevn/platform-core` (structured logging, Prometheus metrics, production guard hooks). Meets pilot-stack baseline; production still requires `verify:production-env` + DevOps runbook (out of S1 A scope).
4. **Traceability** — Dev evidence paths per BE/FE item; QA batch maps work_item_id → command → exit code.

### Controlled drift (accepted for S1 with documentation debt)

| Pattern | Location | Risk | Mitigation in code |
|---------|----------|------|-------------------|
| Group CEO `main` → `holding` for KPI rollup query | `resolveKpiRollupScopeContext` | Medium — wrong generalization could widen reads | Restricted to `tenant=xevn` + `group_*` role + claim `main` + request `holding`; covered by `kpi-rollup-scope.spec.ts` |
| Catalog overview `main` → `holding` | `resolveHrmSettingsCatalogCompanyId` | Medium — catalog SoT confusion | Member-tenant `main` unchanged per spec; group path only |
| Business-master `GET :domain` alias | xbos `business-master.controller` | Low — route duplication | Prefer `/items` in probes; legacy path documented |

**Recommendation:** SA to fold these into one ADR snippet (`ADR-HRM-RBAC-SCOPE-LADDER` or M01 addendum) before S2 CC publish security review (`P1-S2-TM-01`).
