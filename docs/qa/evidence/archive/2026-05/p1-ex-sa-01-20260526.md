## 1. Context summary

Cross-cutting audit of **JWT boundaries**, **named scope helpers** (ADR-GROUP-CEO-MAIN-HOLDING-SCOPE), **RACI legal-entity paths**, and **list ↔ get-by-id / mutate parity** across `hrm-api` and `xbos-api`. Sources: ADR, Nest `common/*-scope*.ts`, controller wiring, unit specs (static; live `jest` blocked in agent shell by workspace path encoding on this host).

**Normative ADR:** `docs/architecture/ADR-GROUP-CEO-MAIN-HOLDING-SCOPE.md` (Accepted 2026-05-24).

**Architecture flow (target state):**

```text
Bearer JWT (tenantId, companyId=main, roleCode)
        │
        ├─► resolveScopeContext ── default strict 409 on tenant/company drift
        │
        ├─► HRM operational SQL
        │     resolveHrmListScope → IN (5 GROUP_MEMBER_SLUGS) when group_ceo + xevn + main
        │     assertResourceInHrmScope OR scoped get*Scoped query on mutate/get-by-id
        │     resolveHrmSettingsCatalogCompanyId → holding partition (catalog only)
        │
        └─► XBOS reads
              resolveKpiRollupScopeContext (main JWT + holding query)
              resolveXbosGroupLegalReadScopeContext (main JWT → holding effective read)
              resolveRaciMatrixJwtScope + assertJwtMayReadLegalEntityPartition (path UUID)
```

## 2. Helper inventory — consistency matrix

| Helper | Package | Gate | Effective read/write key | ADR §4 row |
|--------|---------|------|---------------------------|------------|
| `resolveScopeContext` | HRM + XBOS | Claim-first; **409** on mismatch | JWT `tenantId` + `companyId` (HRM also `company_uuid` slug↔UUID) | Default strict |
| `resolveHrmListScope` | HRM | `xevn` + `group_ceo`/`group_*` + claim/query `main` | SQL `company_id IN` five slugs + master partition | HRM operational lists |
| `resolveHrmSettingsCatalogCompanyId` | HRM | Group rollup scope | Persisted catalog key **`holding`** | Settings catalogs overview |
| `resolveHrmOperationsPersistCompanyId` | HRM | Group rollup | Write UUID → holding slug map | Ops/tasks UUID tables |
| `assertResourceInHrmScope` | HRM | Row `company_id` ∈ scope.companyIds | 404/409 on cross-slug id access | Mutate-by-id guard |
| `resolveKpiRollupScopeContext` | XBOS | Group CEO + JWT `main` + query `holding` | Effective `companyId=holding` | KPI rollup |
| `resolveXbosGroupLegalReadScopeContext` | XBOS | Group CEO + JWT `main` + req `main`/empty/`holding` | Effective `companyId=holding` | Legal/catalog read surfaces |
| `resolveRaciMatrixJwtScope` | XBOS | Group CEO on master | JWT scope for matrix gate (not path UUID) | RACI matrix |
| `assertJwtMayReadLegalEntityPartition` | XBOS | Group CEO bypass tenant match on member LE | Partition tenant check for member CEOs | RACI + org LE UUID |

**Constant alignment:** `HRM_GROUP_MEMBER_COMPANY_SLUGS` in `hrm-list-scope.ts` matches ADR / `HRM_SEED_CARDINALITY_RULES.md` (`holding`, `trsport`, `logistics`, `finance`, `services`). **Consistent.**

**JWT boundary (unchanged invariant):** Group CEO on master remains `companyId=main`; **no** reverse alias (JWT `holding` + query `main` → **409** per ADR §4).

## 3. Scope parity audit (list ↔ get-by-id ↔ mutate)

| HRM module | List / query SQL | Get-by-id / detail | Mutate | Parity verdict |
|------------|------------------|--------------------|--------|----------------|
| **employees** | `resolveHrmListScope` + filters | `getEmployeeById` scoped SQL | `assertResourceInHrmScope` on update/archive | **PASS** |
| **payroll** | `resolveHrmListScope` | — | `assertResourceInHrmScope` on payslip mutations | **PASS** |
| **employee-metadata** | `resolveHrmListScope` | — | `assertResourceInHrmScope` on approve/reject | **PASS** |
| **decisions** | `resolveHrmListScope` | `getDecisionScoped` (id + scope IN) | update/delete via scoped fetch | **PASS** (pattern to replicate) |
| **contracts-insurance** | `resolveHrmListScope` | N/A (list-only surface) | `updateContract` scoped UPDATE; **create** uses raw `payload.company_id` | **CONDITIONAL** — create bypass |
| **recruitment** | `resolveHrmListScope` | N/A | `createCandidate` checks requisition in scope; **`createJobRequisition` no auth scope** | **CONDITIONAL** |
| **performance** | `resolveHrmListScope` | N/A | **`createCycle` no authorization**; evaluations scoped via cycle lookup | **CONDITIONAL** |
| **attendance / leave** | `resolveHrmListScope` / `pushWorkforceEmployeeScopeFilter` | — | Mixed; workforce subquery aligned with ADR | **PASS** (list wave) |
| **operations** | `resolveHrmListScope` + persist resolver | Controller `resolveScopeContext` only | UUID persist mapping | **PASS** with dual-layer gate |
| **settings-catalogs** | Overview uses **`resolveHrmSettingsCatalogCompanyId`** | — | **`sync-from-xbos` passes `scope.companyId` (JWT `main`) not catalog resolver** | **FAIL** — see P0 |

**Controller pattern (HRM):** Most controllers call `resolveScopeContext` at edge (JWT plane `main` only), then services apply `resolveHrmListScope` for SQL. **Consistent** with ADR “409 default + named aliases in services,” except catalog sync gap.
