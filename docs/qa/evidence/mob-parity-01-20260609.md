## 2. Root cause — P0 slug vs UUID (`company_id=holding`)

Diagnostic (nip.io, `uat.nv0001@xe.vn`):

```
company_id=holding     → leave-requests HRM-SYS-001 invalid input syntax for type uuid: "holding"
company_id=<uuid>      → leave-requests HRM-LEAVE-200 Leave requests listed
notifications + holding slug → FAIL
notifications + company_uuid → HRM-NOTIF-200
```

Mobile login returns `default_company_id=holding` + `company_uuid=6efaa5d6-…`. **Attendance list** tolerates slug; **leave-requests** and **notifications/inbox** require UUID — parity break vs web embed (group CEO uses `main` rollup).

**Tag:** `scope_parity` · `slug_uuid_drift` · relates `D-W7-HOME-TASKS-SLUG-01` (home/summary fixed; leave/notifications residual).
