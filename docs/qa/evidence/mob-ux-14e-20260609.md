# MOB-UX-14e — Home Vietnamese company + profile display name

**owner:** dev-mobile

## Problem (sponsor screenshot)

Home `HomeTopBar` showed raw slug **«holding»** and generic **«bạn»** instead of real HRM DB Vietnamese labels and employee `full_name`.

## Root cause

1. `resolveHomeGreeting` used `companyId` slug fallback when `company_display` was English (`XeVN Holding`) or absent.
2. `displayName` came from JWT membership `employee_name` before `GET /employees/:id` returned `full_name`.
3. Home painted immediately with `EMPTY.greetingName = 'bạn'` while profile fetch was in flight.

## Fix

| Area | Change |
|------|--------|
| `companyDisplayVi.ts` | `resolveCompanyDisplayVi()` — holding/main/trsport/logistics/finance/services → Vietnamese via operating-unit registry (API rows or `PILOT_HRM_OPERATING_UNITS` web parity) |
| `dashboardHome.ts` | `resolveHomeDisplayName()` — profile `full_name` > membership > «bạn»; `resolveHomeGreeting` uses new resolvers |
| `DashboardScreen.tsx` | Parallel `fetchEmployeeById` + `fetchHrmOperatingUnits` before paint; `profileReady` gate + skeleton until profile resolved |
| `HomeTopBar` | `companyLabel` Vietnamese only (no raw slug) |
