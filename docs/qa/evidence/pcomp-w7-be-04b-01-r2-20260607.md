## Root cause

`buildWhosOut` used `lr.company_id = $n::uuid` with raw `query.company_id` when scope was not group rollup. Mobile path sends slug `holding` → PostgreSQL `invalid input syntax for type uuid: "holding"`. `buildCelebrations` already scoped via `pushWorkforceEmployeeScopeFilter` on employees (TEXT `company_id`).

---

## Fix

1. **`home.service.ts`** — `buildWhosOut` always calls `pushWorkforceEmployeeScopeFilter(filters, values, scope, 'lr.employee_id')`; removed `lr.company_id ::uuid` branch.
2. **`hrm-list-scope.ts`** — `pushWorkforceEmployeeScopeFilter` else branch (single/multi slug) now uses `employee_id IN (SELECT id FROM employees WHERE company_id = slug …)` so UUID satellite tables (`leave_requests`) resolve slug without casting.
