## Root causes fixed

### UC-CC-03/04 — scope parity (member legal entity UUID)

- Group CEO JWT uses `main` → read scope `holding`, but member rows live under **member `tenant_id` + `main`**.
- `GET /org-foundation/legal-entities` on master returned **0** rows (holding partition only).
- Profile APIs used header scope (`xevn`/`main`) for `assertEntity` → **404** on member `le.id`.

**Fix:** `resolveLegalEntityPartition(entityId)`; aggregated `listGroupMemberLegalEntitiesFlat()` for master/holding/main; `GET legal-entities/:entityId`; PUT resolves partition from UUID; profile service uses org resolver.

### W3-5 — workflow PUT 500

- `UPDATE` SQL used `$4..$9` while passing unused `$3` (`companyId`) — driver/parameter mismatch risk.
- PUT body from portal sends `code` + `graph` without `workflowCode`; graph jsonb needed normalization.

**Fix:** 8-parameter UPDATE (`$1` id, `$2` tenant, `$3..$8` fields); `normalizeJsonbPayload`; PUT requires `name` only; accepts `workflow_code` / nested `payload.graph`.

### HRM service-requests `page_size=10` → 400

- `ListServiceRequestsQueryDto` lacked `page` / `page_size` (ValidationPipe rejected unknown query keys).

**Fix:** Aligned with `ListTasksQueryDto` (`@Type`, `@IsInt`, `@Max(100)`).

### UC-CC-04 validation (W3-3)

- Invalid PUT used snake_case `tax_code` / `charter_capital` — not mapped to `LegalEntityInput`.
- Added normalization + deterministic 400 messages (MST / vốn điều lệ).
