## Executive verdict

**READY_FOR_QA** — Bottom tab bar, center FAB, FAB action sheet, sticky footers, and scroll padding now use `resolveBottomSafeInset()` with **24dp Android fallback** when `SafeAreaInsets.bottom === 0` (3-button navigation). Device QA marker `tab-bar-safe-zone` added for adb/uiautomator clearance checks.

---

## Root cause

On Android devices with **3-button navigation**, `react-native-safe-area-context` often reports `insets.bottom = 0`. `RootNavigator` used raw `insets.bottom` for `tabBarStyle.paddingBottom` and height, causing tab labels/icons to overlap the system nav bar.

---

## Changes delivered

| Area | File(s) | Change |
|------|---------|--------|
| Inset helper | `src/theme/layoutInsets.ts` | `resolveAndroidNavigationBarInset()`, `resolveBottomSafeInset()`, `ANDROID_NAV_BAR_FALLBACK_DP=24`, `TAB_BAR_SAFE_ZONE_TEST_ID` |
| Tab bar | `src/navigation/RootNavigator.tsx` | `paddingBottom` + `height` via resolved inset; absolute safe-zone marker View |
| Center FAB | `src/navigation/checkInFab.ts`, `CheckInFabOverlay.tsx` | `resolveCheckInFabBottom` uses resolved bottom inset |
| FAB sheet | `FabPrimaryActionSheet.tsx` | `sheetBottom` uses resolved inset |
| Scroll / footer | `AppScreenLayout.tsx` | `Math.max(useBottomTabBarHeight(), resolveTabBarHeight(...))`; standalone footer uses resolved inset |
| Sticky footer | `StickyFooter.tsx` (via helper) | `resolveStickyFooterPaddingBottom` applies Android fallback when not above tab bar |
| Tests | `layoutInsets.test.ts`, `checkInFab.test.ts` | Android 0→24dp, iOS unchanged, FAB centering with fallback |

**Preserved:** 4-tab IA, API/auth/scope, boot `index.ts`, MOB-UX-08 scroll order.
