## Module detail

### 1. catalog-extensions (`catalog-extensions.service.ts`)

**Shared pattern (good — SRP):**

```typescript
private scopedList(companyId: string, authorization?: string) {
  const scope = resolveHrmListScope(authorization, companyId);
  pushCompanyIdFilter(filters, values, scope.companyIds);
  return { scope, filters, values };
}
```

- **sales-data, bonus-policies, insurance/tax participants, face-data (list):** all use `scopedList` → group CEO `main` → `company_id = ANY(member slugs)` ✓
- **Mutations (PATCH/DELETE)** on sales, bonus policy, insurance/tax: peek `company_id` then `assertResourceInHrmScope(peek, scope)` ✓

**GWC gaps:**

| ID | Location | Problem | Risk | Fix |
|----|----------|---------|------|-----|
| CE-01 | `syncSalesData` L327–335 | Updates `WHERE company_id = $1` with persist slug only | Group CEO sync may miss member-company rows in rollup | Apply `scopedList` filters (ANY) on UPDATE |
| CE-02 | `deleteFaceData` L695–702 | Single `resolveHrmPersistCompanyIdText`; no peek/assert | Cross-scope delete if row exists under member slug | Peek row → `assertResourceInHrmScope` |
| CE-03 | `createBonusPolicyParticipant` L437–461 | No verify `policy_id` belongs to scoped company | Orphan/wrong-policy attach | Peek policy with `assertResourceInHrmScope` |
| CE-04 | `storeUploadedFile` L799–813 | No `company_id` / scope in path or DB | Any authed user shares global upload dir | Require `company_id` query; prefix `uploads/{companyId}/`; optional JWT scope check |

**Out of W3 slice (note only):** `listGuideContent` / subscription helpers use persist or optional filter without full rollup on read — not in TM dispatch scope for this work item.

### 2. Employee assets (`employee-profile.service.ts`)

- **List:** `listScopedRows` → `employees.getEmployeeById` (uses `resolveHrmListScope` on `query.company_id`) then filters assets by `employee.company_id` ✓
- **Mutate:** `insertProfileRow` / `updateProfileRow` / `deleteProfileRow` re-call `getEmployeeById` ✓
- **No** `GET /employees/:id/assets/:assetId` — Q5 “GET-by-id” satisfied via **parent employee** resolver (same as list gate).

**GWC hardening (non-blocking):** `updateProfileRow` / `deleteProfileRow` should peek asset row and `assertResourceInHrmScope` on `company_id` (defense-in-depth vs corrupt rows).

### 3. `POST catalog-extensions/files/upload`

- Controller: `assertAccess` + multipart only (`catalog-extensions.controller.ts` L336–351).
- Service: filesystem write under `HRM_FILE_UPLOAD_DIR` / `uploads/hrm-files` with feature prefix only.
- **Parity:** N/A for list/GET; **tenancy GWC** as CE-04.

### 4. `candidate-evaluations` (post BE fix)

- **List:** `listCandidateEvaluations` — `resolveHrmListScope` + `e.company_id = ANY($1::text[])` on evaluation alias (not bare `WHERE company_id =`) ✓
- **Delete:** `pushCompanyIdFilter` on `scope.companyIds` ✓
- **Regression:** `recruitment-catalog.service.spec.ts` — expects `e.company_id = ANY` and no invalid `WHERE company_id =` on eval table ✓
- Prior QA 500 (`HRM-SYS-001`) addressed in `P1-QUAL-BE-W2-EVAL-01` (subagent-stop 2026-05-30).
