### INC-DATE-ATT-SHEET — Thêm bảng chấm công

| Layer | Spec says | Symptom / code does (read-only BA) | Gap class |
|-------|-----------|--------------------------------------|-----------|
| **Display** | `dd/MM/yyyy` (BR-UX-DATE-01 · AC-UX-DATE-01 · SRS đầu vào kỳ) | Placeholder `DD/MM/YYYY`; list kỳ dùng `formatDisplayDate` | Align display OK nếu parse đúng |
| **Picker** | L-DATE: **picker MUST mở** để chọn ngày | Icon `Calendar` trang trí `pointer-events-none` trên `Input` text — **không** có Popover/Calendar/DayPicker | **P0 UX** — «picker không mở» = đúng hiện trạng (không có picker) |
| **Manual entry** | Accept `dd/MM/yyyy` **và** `d/M/yyyy` (padded + unpadded) → commit ISO | `handleAddSheet` split `/` rồi ghép `${y}-${m}-${d}` **không pad** → `2026-1-1` | **P0 parse** |
| **Network** | `POST …/attendance-sheets` body `start_date`/`end_date` = **ISO date-only** `yyyy-MM-DD` (`@IsDateString`) | Unpadded / invalid string → ValidationPipe **400**; FE toast «không hợp lệ» | FE phải emit padded ISO; BE contract **đúng** — không đổi DTO để nhận `2026-1-1` |
| **FE error copy** | BR-ATT-SHEET-04: thiếu ngày / start > end → từ chối **kèm thông báo rõ** | Cần message rõ: format sai vs kỳ đảo vs 400 API | FE validation trước submit + map 400 |
| **Journey** | **J-HRM-06b** · AC-ATT-SHEET-01..06 · UF-HRM-16 | Matrix từng 🟢; **reopen P0 date** trên cùng journey — không đè AC sheet empty/storm | Retest J-HRM-06b date slice |

**Root-cause (BA):** Form add-sheet **không dùng** SoT `ViDateField` / `parseViDisplayToIsoDate` (đã accept unpadded → padded ISO). Icon calendar giả → user tưởng picker hỏng.

### INC-DATE-CO-FOUND — Ngày thành lập công ty (+ MST/email/phone «—»)

| Layer | Spec says | Symptom / code does (read-only BA) | Gap class |
|-------|-----------|--------------------------------------|-----------|
| **Display** | User-facing date `dd/MM/yyyy`; empty → `—` an toàn | View dialog: `founded_date` format OK **khi có giá trị**; hiện **trống / —** | Data null |
| **Picker** | L-DATE: chọn ngày được (Popover+Calendar hoặc `ViDateInput` + calendar) | Edit form có `Popover`+`Calendar`; trong `Dialog` Radix có rủi ro popover không nổi / focus trap | **P0 UX** nếu click không mở calendar |
| **Manual / bind** | Ngày thành lập + MST / email / phone là thông tin pháp nhân vận hành (meeting BRD + form labels) | Portal embed load qua `fetchGroupMemberUnitsForHrm` → map **hardcode** `founded_date`/`tax_code`/`email`/`phone` = **`null`** | **P0 bind** — UI «—» dù DB/XBOS có thể có field |
| **Persist** | Lưu → API 2xx → F5 còn `dd/MM/yyyy` (AC-UX-DATE-02) | `onSubmit` build `companyData` incl. `founded_date: yyyy-MM-dd` nhưng **không gọi API persist** — toast + `fetchCompanies()` → lại null | **P0 fidelity** FE (+ SA SoT endpoint) |
