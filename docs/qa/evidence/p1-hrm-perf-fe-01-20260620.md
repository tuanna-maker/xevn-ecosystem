## FE-01 — Before / after (API call estimate)

### Root cause (before)

`HrmWorkspaceRoute` set `key={target}` where `target` included:
- full HRM path per tab (`/hr/employees`, `/hr/contracts`, …)
- `cacheBust: Date.now()` bumped on every `portalSuffix` change

→ **100% iframe remount** on each CC HRM sidebar click → full mount API storm (~15–17 calls) repeated.

### Fix

| Layer | File | Behavior |
|-------|------|----------|
| Portal | `HrmWorkspaceRoute.tsx` | `key={embedScopeKey}` (tenant+company only); initial `src` from deep link; tab change → `postPortalEmbedNavigate` |
| Portal | `portalEmbedNavBridge.ts` | `xevn.portal.embed.navigate` postMessage |
| HRM | `portalEmbedNavBridge.ts` + `PortalEmbedRouterSync.tsx` | Listen + `navigate(path)`; `syncHrmLocationToPortalParent` for F5 deep links |

### Call count estimate (pilot ~1107 NV)

| Scenario | Before | After |
|----------|--------|-------|
| CC tab switch (dashboard → employees → contracts) | **~45–51** (3× full mount) | **~0** mount replay (in-app route only) |
| First HRM embed open | ~17 | ~17 (unchanged — one mount) |
| F5 deep link `/command-center/hrm/employees/:id` | ~16+ | ~16+ (one mount with correct path) |
| Scope change (tenant switch) | remount | remount (intentional) |

**Net:** Tab navigation eliminates **~15–17 API calls per switch** (100% of prior redundant mount storm).
