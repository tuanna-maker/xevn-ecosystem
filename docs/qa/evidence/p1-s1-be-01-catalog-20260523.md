## Scope delivered (S1 minimal slice)

### config-sync (publish + read)
- `POST /config-sync/catalog/:catalogKey/publish` — JWT/body `tenantId`/`companyId` aligned via `resolveScopeContext` (409 `SCOPE_CONTEXT_MISMATCH` when e.g. JWT `holding` vs body `main`).
- `GET /config-sync/catalogs`, `GET /config-sync/catalog/:catalogKey` — existing scope + target validation unchanged.
- Service layer: deterministic validation (`XBOS-VAL-*`), version/checksum publish upsert, scoped `(tenant_id, company_id, catalog_key)` uniqueness.

### catalog-governance (extension workflow)
- Closed ADR gap: scope guards on all routes (previously internal-auth only).
- Group CEO paths (`inbox`, `approve`, `reject`, `instances`, seed) default to `xevn`/`holding` and enforce JWT alignment.
- `workflows/start` validates member unit scope on `memberTenantId`/`memberCompanyId`.
- `extension-requests` uses `resolveTenantOnlyContext` for `tenantId` query.
- DTO: `StartCatalogWorkflowDto` with class-validator.
