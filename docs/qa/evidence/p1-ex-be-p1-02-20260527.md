## 1. Problem (P1-02)

TM-03 / SA-03: mutate-by-id paths in several HRM modules relied on scoped SQL only (or no scope predicate). `assertResourceInHrmScope` was adopted in **employees**, **payroll**, **employee-metadata** only — IDOR-class risk on contracts, recruitment, decisions, attendance, operations.

---

## 2. Changes

### 2.1 Core helper (`hrm-list-scope.ts`)

- `assertResourceInHrmScope` now accepts **TEXT slugs** and **UUID** `company_id` values via `companyIdsToUuidList(scope.companyIds)` (group CEO `main` rollup ↔ holding UUID).

### 2.2 Service adoption (mutate-by-id)

| Module | Methods guarded |
|--------|-----------------|
| **contracts-insurance** | `updateContract`, `deleteContract` — load row `company_id`, assert, then scoped SQL |
| **recruitment** | `updateInterviewStatus` |
| **decisions** | `updateDecision`, `deleteDecision` (after scoped fetch) |
| **attendance** | `updateStatus`, `updateUpdateRequest`, `approveUpdateRequest`, `rejectUpdateRequest`, `deleteUpdateRequest` |
| **leave-requests** | `approveLeaveRequest`, `rejectLeaveRequest` |
| **operations** | `updateTaskStatus`, `updateServiceRequest`, `deleteServiceRequest`, `approveServiceRequest`, `rejectServiceRequest` |

Controllers pass `authorization`, `x-company-id` (default `main`), `x-tenant-id` into service mutates where missing.

**Unchanged (already guarded):** `employees`, `payroll`, `employee-metadata`.
