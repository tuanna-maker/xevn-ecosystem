# Pull Request Checklist

## 1) PR Context
- Work item:
- Type: feature / fix / refactor / chore
- Scope summary:
- Risk level:

## 2) Change Quality
- [ ] Coding convention and maintainability reviewed.
- [ ] SOLID/design impacts reviewed.
- [ ] Business rules/acceptance behavior verified.
- [ ] UI/UX impact reviewed (if applicable).

## 3) Security and Reliability
- [ ] No secrets/sensitive files in diff.
- [ ] Security impact assessed.
- [ ] Performance/reliability impact assessed.
- [ ] Observability/logging impact reviewed.

## 4) Evidence
- [ ] Build passed.
- [ ] Tests passed (unit/integration/regression as applicable).
- [ ] Security scan passed.
- [ ] Linked evidence paths in repo/CI output.

## 5) Review and Merge Readiness
- [ ] PR reviewed by required roles.
- [ ] All review comments resolved.
- [ ] Merge strategy confirmed (squash/rebase/merge per policy).
- [ ] Ready for merge to protected branch.
